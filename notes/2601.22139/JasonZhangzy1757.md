**when: decided by the trained reasoning model itself while it thinks. When it reaches a step where it feels a condition is missing, it writes a question inside an `<asking>` tag, and goes on reasoning after the user replies, up to 5 rounds; there is no outside trigger and no separate controller. "When to ask" is learned from the reward: a wrong answer always gets 0, so not asking about a missing premise gets no points; when the answer is right, each extra round of asking lowers the efficiency score, so unnecessary questions are pushed down. what: free-text questions the model writes itself; a judge model gives each question a helpfulness score from 0 to 1 by "fits the intent, useful, clear", which is multiplied into the reward. Credit: one score for the whole trajectory.**

**Problem:** In reasoning tasks like math, code and document editing, the user's first sentence often does not say everything. A reasoning model fills in an assumption by itself where a condition is missing and keeps reasoning, reasons for a long time, and still gets it wrong. The paper wants the model to stop at the step where a condition is missing, ask the user, get the reply, and then go on.

The task agent is DeepSeek-R1-Distill-Qwen-7B: in the first stage, data is created and SFT teaches it the format of "inserting questions into its thinking"; in the second stage, reinforcement learning teaches it when to ask and what to ask. The simulated user (Llama-3.1-8B-Instruct, holding the full problem; its prompt tells it to say little, let the AI ask, sometimes make mistakes, and not repeat the problem); the judge (gpt-4o-mini) gives each question a helpfulness score; right or wrong comes from the task's own checker.

**Stage one: build "think—ask—answer" data and use SFT (next-token prediction) to teach it the format of "inserting questions into its thinking".** Take a set of open-ended questions, let a frozen DeepSeek-R1 write full reasoning chains, and split them into sentences; for each sentence, compute the average negative log-probability the model gives to each token of the sentence (predictive entropy). The top k% least confident sentences are set as places to ask. At each such place, GPT-4o-mini inserts one round of "question and answer". 4,000 examples are used for supervised fine-tuning; the loss covers the whole sequence, including the inserted questions and the simulated answers.

**Stage two: US-GRPO, learning when to ask and what to ask in an environment with a simulated user.** The problems come from CollabLLM's three multi-turn datasets (Math-Chat, BigCodeBench-Chat, DocEdit-Chat). A problem comes in, and the simulated user first writes, from the full problem, an opening request that does not say everything on purpose. Here 8 rollouts are split off: in each, the model reasons inside `<think>`, writes `<asking>…</asking>` where it wants to ask, the simulated user replies with one sentence according to the full intent, and the model goes on reasoning; it can ask again, up to 5 rounds; the model decides by itself when to stop asking, and writes the final answer after `</think>`. When each run ends, one total score is computed, two parts added up:

a) Output score: a right answer gets a base score, a wrong answer gets 0 (guessing a missing premise leads to a wrong answer and gets nothing, so the model will ask.) b) Reasoning score: only when the answer is right and it asked, equal to base score × efficiency × helpfulness. Efficiency = (5 − number of asking rounds) ÷ 4: asking 1 round gives 1, asking 5 rounds gives 0; the goal is to ask less. Helpfulness: the judge reads the full intent, the conversation history and this question, and scores 0, 0.2, …, 1.0 by "fits the intent, useful, clear"; the goal is that the questions asked really help the reasoning go on.

Side note: if a right answer without asking gets only the base score, and a right answer after one useful question gets up to twice as much, will the model also want to ask on clear problems? The paper's answer relies on helpfulness: if the problem is already clear, the judge gives the question a low score, so the reasoning score is small. But in evaluation it still asks on about 30% of the problems where it should not.

- Data: CollabLLM's Math-Chat / BigCodeBench-Chat / DocEdit-Chat; the simulated user holds the full problem and is told to say little and let the AI ask.
- Baselines of the same kind: STaR-GATE (learns to clarify when facing ambiguity), CollabLLM (RL with multi-turn lookahead); the baseline group is built on Qwen2.5-Math-7B-Instruct, which has no reasoning.
- Heuristic baselines: the original models answering directly (Qwen2.5-Math-7B-Instruct, DeepSeek-R1-Distill-Qwen-7B), and a prompt that tells the model to ask (Proactive Prompt).
- Also tested on: MMLU, MMLU-Pro, TriviaQA, SQuAD (knowledge and QA), MIP-GSM8K / MIP-MATH (math problems with a missing premise), Abg-CoQA (judge whether to ask).

The idea is actually similar to the ones above, and here we can see a pattern. Forcing the model to ask through reward shaping is one kind, but it needs the original task itself to allow a simulated user and interaction; if it does not, another way is to build data and use SFT to learn the asking format first, and on top of that, use RL to learn a reward that encourages asking.
