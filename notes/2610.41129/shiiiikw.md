When Should AI Agents Ask studies how multiple agents sharing one user's limited attention should schedule questions, independent searches, and other work. The objective accounts for task delays, search costs, interruptions, and the user's effort in answering. Given the user's availability probability, search success probabilities, remaining workloads, and costs, the authors use dynamic programming to calculate optimal costs. Their pairwise coordination policy (PCP) first calculates the optimal cost for each task with exclusive access to the user, then the extra cost for each pair sharing that user. It uses those quantities to estimate the cost of running several tasks together and decide which agents should ask, search, or work, and which question the user should answer first. An agent can work or search while waiting and withdraw its question if it finds the answer.

The authors build a scheduling simulation, mainly with three or four concurrent tasks, varying user availability, search success, and remaining work. A second experiment uses four parallel procurement tasks. The user's maximum acceptable delivery time is hidden, and each task requires evaluating four suppliers and choosing the one with the lowest total price among those that meet the deadline. In this experiment, gpt-6.1-sol reads the materials and performs calculations, an external policy controls when to ask, and a scripted user answers at most one question per available time slot.

The simulation compares PCP with Singleton, which ignores competition for the user, and Always Ask, which never searches and submits the next question by task weight when the pending queue is empty. Random-order Ask chooses the next question at random. Search Once Then Ask finishes independent work, searches once, and asks only if the search fails. For small instances, exact dynamic programming supplies the optimal policy for comparison. The procurement experiment compares PCP, Singleton, Always Ask, and Search Once Then Ask using identical materials, search outcomes, and user availability schedules.
