真实用户的需求常常说得很模糊：论文把 SWE-Bench 的 issue 从平均 194 个词改写成 11 个词，只剩一句"去掉某一列时报了个让人困惑的错"。agent 要么瞎做，要么问；问得多用户烦，问到用户答不上来的更烦；而且不同用户偏好不同，有的只在开头答问题，有的只答选择题，有的根本不想被问。文章想要的是：agent 在做任务的过程中自己决定什么时候向用户发问，只问用户答得上的，并按这个用户的偏好来问。

执行 agent（Seed-OSS-36B-Instruct，被训的）是一个 ReAct 循环：每一步写一段推理，再调一个工具。工具里除了任务工具，多了一个 ask_user。用户模拟器（GPT-5-Nano，不训）拿着两样东西：完整的精确需求，和这一条对话的用户偏好。一条对话这样走：模糊需求进来，agent 每步要么调任务工具，要么调 ask_user 发一个问题。

问题到了模拟器那里，它先判这个问题要用户费多少力：答案能从完整需求里直接找到的，照答，记低费力；问到完整需求之外、用户只能答"不知道"的，记中费力；需要用户自己去查代码或文档才能答的，给一个提示，记高费力。（判法按任务定自定义）。答法还要按偏好改：只答选择题的用户，碰到不是选择题的就答"不知道"。直到 agent 给出最终答案。

**自己创建了一个数据集（UserVille）。** 取 SWE-Gym 的函数定位任务和 BrowseComp-Plus（450 训练 / 100 测试）的精确需求，让一个 LLM 改写成模糊版：最多保留一个关键细节，其余泛化。精确版只有模拟器看得到。每个任务复制 13 份：12 份模糊需求各配一种训练偏好，1 份精确需求。偏好一共 20 种，12 种训练、8 种只在测试时出现（意大利语、JSON、恰好三句、带一个笑话、全大写……）。

**分数：一条对话一个分，三项相加。**

a) 任务本来的分。b) 主动性分：目的是只问用户答得上的，全部问题都是低费力 +0.05；每个中费力问题 −0.1；每个高费力问题 −0.5。另外，对模糊需求一个问题不问就给出错答案的，整条记为高费力。c) 个性化分。目的是按这个用户的偏好来问。完全符合 +0.05；每次违反按该偏好的具体规则扣.

**怎么训：GRPO。** 每步取 64 个（任务，偏好）样本，每个从当前策略采 8 条对话。优势 = （总分截到 0 到 1 之后 − 8 条的均值）÷ 8 条的标准差，乘到这条对话里模型生成的全部 token 上：推理、工具调用、问题、最终答案；模拟器的回复和工具返回不算。用了 DAPO 的 clip-higher 和 token 级损失；学习率 1e-6，200 步。

"什么时候问"没有单独的部件，全靠三项分的差压出来：模糊需求下不问就答错，任务分低、还记成高费力；问一个用户答得上的问题，任务分涨、还加 0.05；问用户答不上的，扣分。训练过程里每会话的问题数从 0.5 升到 1.2，涨的基本是低费力问题；中费力问题先升后降；去掉主动性分的消融，中、高费力问题越来越多。而低费力加 +0.05 而不只罚则是调参（附录 C 的初步实验）。

另做了真人实验：33 个有编程经验的人，SWE-Bench 前 100 题 × 3 个模型。没有比对别的论文的方法。比的是 GPT-5 系列直接跑和自身消融。**when和what都极尽自由的一篇文章。核心也就是reward shaping。**

- 数据：自建 UserVille（SWE-Gym / SWE-Bench-Verified 的函数定位：在代码库里找出要改的函数；BrowseComp-Plus：要多次搜索的难问答）。
